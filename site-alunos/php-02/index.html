Na L1 a ficha de um aluno era um array associativo. Quando muitas coisas têm as mesmas informações (e as mesmas ações), a gente cria uma classe: o molde que diz o que todo aluno tem. Cada aluno de verdade é um objeto, criado com new. A classe é a forma; os objetos são os bolos. Para acessar uma propriedade o PHP usa a setinha -> (o ponto do JavaScript: carro.marca vira $carro->marca).

  
Experimente: crie um terceiro carro com a sua marca favorita. Depois tente $meuCarro->ano = "velho"; e veja o PHP reclamar do tipo.







  
Uma classe não guarda só dados: guarda também as ações sobre esses dados. Uma função dentro da classe se chama método, e é chamada com a setinha: $pedido->total(). Dentro do método, $this quer dizer "este objeto aqui": $this->itens são os itens do pedido que chamou o método (igual ao this do JavaScript).

  
Experimente: adicione uma sobremesa ao pedido. Depois crie um $pedido2 = new Pedido() e veja que cada pedido tem os próprios itens.







  
Preencher propriedade por propriedade cansa (e dá para esquecer uma). O construtor __construct é um método especial que roda sozinho no new: o que você passa em new Aluno("Ana", "Laravel") chega nele. O PHP 8 tem uma forma curta, muito usada no Laravel: escrever public no parâmetro do construtor já cria e preenche a propriedade.

  
Experimente: crie new Aluno("Caio") sem o curso e leia o erro. Depois crie um professor passando a matéria.







  
public pode ser usado de qualquer lugar; private só de dentro da própria classe. Isso se chama encapsulamento: o saldo da conta é private, então ninguém faz $conta->saldo = 1000000. Quem quer mexer no saldo tem que passar pelos métodos, que conferem as regras (não depositar valor negativo, não sacar mais do que tem). Existe ainda o protected: privado, mas as classes filhas enxergam (próximo exemplo).

  
Experimente: tire o // da última linha e execute: o PHP não deixa mexer no saldo por fora. Depois tente depositar -50.







  
Com extends, uma classe herda tudo de outra (propriedades e métodos) e só acrescenta ou troca o que for diferente. Professor extends Pessoa: todo professor é uma pessoa, com algo a mais. parent:: chama a versão da classe mãe. É assim no Laravel inteiro: todo controller extends Controller e todo model extends Model, e é por herança que o seu model ganha prontos métodos como all(), find() e save().

  
Experimente: crie uma classe Coordenador extends Professor que troca o apresentar() de novo. Depois apague o apresentar() do Professor e veja qual versão roda.







  
Algumas coisas são da classe, não de um objeto: uma constante (const) ou um método static. Para usá-las não precisa de new: usa-se o quatro-pontos ::, como em Escola::NOME. Dentro da classe, self:: aponta para ela mesma. Você vai ver muito :: no Laravel: Route::get(...), Aluno::all() e o AlunoController::class, que dá o nome completo da classe como texto.

  
Experimente: matricule mais dois alunos e veja o total subir. Depois crie uma constante CIDADE e mostre.







  
Na L1, a turma era uma lista de arrays associativos. No Laravel, quando você busca no banco (Aluno::all()), volta uma lista de objetos, e você acessa cada campo com a setinha: $aluno->nome. Tudo o que você sabe de arrays continua valendo: foreach, count, array_filter, array_map.

  
Experimente: adicione um produto esgotado e um disponível. Depois calcule o preço médio dos disponíveis.







  
Num projeto grande existem centenas de classes, e duas podem ter o mesmo nome. O namespace é o "sobrenome" da classe: App\Models\Aluno é a classe Aluno da "família" App\Models. Para usar uma classe de outro namespace, você importa com use (como o import do JavaScript). No Laravel, cada classe fica no seu arquivo e o namespace segue a pasta: App\Models\Aluno mora em app/Models/Aluno.php. Aqui, como só temos um arquivo, cada bloco namespace { } faz o papel de um arquivo.

  
Experimente: apague a linha use App\Models\Aluno; e leia o erro: sem o use, o PHP procura um Aluno na família errada.







  
Um projeto Laravel novo já vem com as pastas organizadas, e cada tipo de arquivo tem o seu lugar: é o que se chama de convenção. Quase todo dia você vai abrir só quatro lugares: routes/web.php (as URLs), app/Http/Controllers (quem atende cada URL), app/Models (os dados) e resources/views (o HTML). E o nome completo de qualquer classe diz onde está o arquivo dela.

  
Experimente: adicione "storage" (arquivos enviados e logs) e "tests" (testes automáticos) à lista. Depois troque a classe do final por App\Models\Curso.







  
Quando o navegador pede /sobre, quem decide o que responder é a rota. No Laravel, as rotas ficam em routes/web.php e são assim: Route::get('/sobre', function () { return 'Sobre'; });. Para ver que não tem mágica, aqui está um roteador de brinquedo feito só com o que você já sabe: uma classe com um array estático de URLs e funções. Se nenhuma rota bate com a URL, a resposta é o famoso 404. Daqui para a frente, este playground já traz um Route, um view() e um visitar() prontos (como o dd), parecidos com os do Laravel.

  
Experimente: crie a rota /cursos e visite de novo. Depois visite /Sobre com S maiúsculo.







  
Com 50 páginas, um web.php cheio de funções vira bagunça. Por isso a rota só aponta para um controller: uma classe que junta as ações de um assunto (tudo de cursos no CursoController). [CursoController::class, "index"] quer dizer "chame o método index dessa classe". Um pedaço da URL entre chaves, como {id}, chega como parâmetro do método. No Laravel, o controller é criado com php artisan make:controller CursoController.

  
Experimente: visite /cursos/2. Depois crie a rota /cursos/{id}/aulas chamando um método novo aulas($id).







  
O controller não escreve HTML: ele junta os dados e entrega para uma view, o arquivo de HTML com buracos que você viu no fim da L1. view("cursos.index", [...]) quer dizer "use o arquivo resources/views/cursos/index"; cada chave do array vira uma variável dentro da view ("titulo" vira $titulo). Aqui o criar_view faz o papel desse arquivo. Clique em 🌐 ver como página para ver o resultado.

  
Experimente: passe mais uma chave "professor" => "Rita" e mostre na view com <?= $professor ?>.







  
Juntando tudo, este é o caminho de todo pedido no Laravel: ① o navegador pede /alunos; ② a rota diz qual controller atende; ③ o controller pede os dados ao model (Aluno::all()); ④ entrega os dados para a view; ⑤ a view monta o HTML, que volta para o navegador. Cada bloco namespace abaixo é um arquivo do projeto, na pasta certa. Clique em 🌐 ver como página.

  
Experimente: adicione um aluno no all(). Depois crie a rota /alunos/aprovados com um método aprovados() que filtra a lista com array_filter.
